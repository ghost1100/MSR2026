# Automatic Testing Detection Evaluation

This document explains the dataset, how it was created, how to reproduce evaluation metrics (precision/recall), and how to inspect false positives/negatives.

## Files added
- `scripts/evaluate_auto_testing.py` — computes precision/recall and writes per-row evaluation to `outputs/auto_testing_evaluation.csv`.
- `scripts/analyze_false_positives.py` — extracts false positives/negatives and writes summaries and examples to `outputs/false_*.csv` and `outputs/false_positive_summary.txt`.
- `sql/pr_analysis.sql` — SQLite script to import the CSV, create a normalized view, compute confusion matrix, and extract FP/FN rows.

## Source dataset
- `comprehensive_pr_manual_verification_dataset.csv` — generated by `create_comprehensive_pr_dataset.py` (see repository root). That script samples PRs, extracts title/body, runs heuristic keyword detection and framework detection, and writes columns including:
  - `pr_id`, `agent`, `pr_title`, `pr_body`, `html_url`, `was test included Y/N` (manual label column), `auto_testing_keywords_found`, `test detection` (auto confidence: `Low`/`Medium`/`High`), etc.

How the CSV was generated (short):
- Run `python create_comprehensive_pr_dataset.py` which reads `data/raw/aidata.csv`, samples PRs, and writes the CSV `comprehensive_pr_manual_verification_dataset.csv`.

## How to reproduce the evaluation
1. Ensure dependencies are installed: `pip install -r requirements.txt` (or `pip install pandas numpy`).
2. Compute automatic metrics:
   ```bash
   python scripts/evaluate_auto_testing.py --csv comprehensive_pr_manual_verification_dataset.csv
   ```
   This prints metrics and writes `outputs/auto_testing_evaluation.csv` and a per-row evaluation CSV.

3. Investigate false positives and false negatives:
   ```bash
   python scripts/analyze_false_positives.py --csv comprehensive_pr_manual_verification_dataset.csv
   ```
   This writes:
   - `outputs/false_positives.csv` (all FPs)
   - `outputs/false_negatives.csv` (all FNs)
   - `outputs/false_positive_summary.txt` (heuristic keyword and agent summary)
   - Example files with sampled rows for manual inspection

## SQL reproduction (SQLite)
1. Start `sqlite3 pr.db` (or your preferred SQLite DB tool)
2. In the sqlite prompt, import and run analysis commands:
   ```sql
   .mode csv
   .import comprehensive_pr_manual_verification_dataset.csv pr_raw
   .read sql/pr_analysis.sql
   ```
3. The SQL creates a normalized view `pr_norm` and runs queries to compute counts and confusion matrix. It also contains example queries to export false positives/negatives to CSV using `.once` + `SELECT`.

## Why false positives happen (summary of findings)
We inspected false positives (auto_conf='high' but manual label indicates no tests) and found:
- The token `test` (or `testing`) appears in most FP rows (e.g., 'test' appears in 81 of the 82 FPs). The heuristic is often triggered by mentions in the PR title/body, even if no test files were added.
- Common causes:
  - Documentation or README changes that mention tests or test plans ("Add testing instructions")
  - CI/workflow or infra changes referring to 'test infrastructure' rather than adding tests
  - PR descriptions that plan to add tests ("will add tests") but don't include them
  - Ambiguous textual mentions (e.g., 'test environment', 'unit test guidelines')
- Agents with higher FP rates: `Devin`, `OpenAI_Codex`, `Claude_Code`, `Copilot` — these agents frequently include test-related wording in their generated PR text even when code changes don't add tests.

## Next steps & recommendations
- Improve heuristic: require presence of test files or file path patterns (e.g., changes to `tests/`, filenames ending with `_test.py`, `spec/`, `__tests__`) in PR diffs rather than only scanning title/body text.
- Optionally use a small classifier trained on title/body + file paths + keywords to reduce ambiguous keyword hits.
- Manual review of sampled FPs (see `outputs/false_positive_examples.csv`) to refine rules.
